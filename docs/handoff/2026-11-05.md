## Architecture in brief

- **Discovery.** A plugin embeds `<AssemblyName>.config.schema.json`. `SchemaCatalog` scans the loaded assemblies once, in `OnLoaded`, and parses each schema (`PluginSchema`). An unreadable or invalid schema never takes the host down: its key goes into `RejectedKeys`, or the catalog turns `Incomplete`.
- **Forms.** `www/` is a static page served through `IWebInterface`; it holds no data. It builds forms from the schema and talks to `PluginConfigController` under `/Api/PluginConfig/`, where ASF's `IPCPassword` middleware applies. `SchemaValidator` checks a value before anything is written.
- **Files.** `ConfigFile` reads and writes one plugin key in `ASF.json` (`BotFiles` finds `config/<bot>.json`), keeps every other key, and refuses a save whose version is stale. A version is an HMAC with a per-process random key.
- **Secrets.** `writeOnly` fields never leave the host (`Secrets`): reads drop them and name the set ones, a save that omits one keeps it, `ClearSecrets` removes one.
- **Raw editor.** For plugins without a schema (`RawKeys`). It refuses ASF's own keys, every key with a schema, and everything while the catalog is incomplete. Raw reads need a real `IPCPassword`.
- **Writes without a password.** Only with the host's own opt-in, `ASFPluginConfig.AllowWritesWithoutIPCPassword` (`HostSettings`), off by default.
- **Updates.** The page's update button calls ASF's own `POST /Api/Plugins/Update`; the plugin updates itself through `IGitHubPluginUpdates`.

## Rules learned the hard way

- **ASF's OS-specific builds are trimmed, and a local build proves nothing about that.** Run `tools/TrimCheck` after any change that touches a framework API; CI's `trimmed-asf` job does. Missing so far: `JsonNode.ToJsonString`, `JsonElement.TryGetProperty(string)`, `JsonProperty.NameEquals` and `WriteTo`, `Enumerable.Order(comparer)`, `[HttpPut]`, `NotFound(object)`, `Conflict(object)`, `HMACSHA256.HashData(byte[], byte[])` (the span overload works), `File.GetUnixFileMode` (path and handle), `FileSystemInfo.UnixFileMode`, `File.SetUnixFileMode(SafeFileHandle, ...)` (the path overload works), and `AppDomain.AssemblyLoad` with its args and delegate. `File.Copy`, `File.OpenHandle` and `AppDomain.GetAssemblies` are there.
- **Fail closed.** When the plugin cannot tell whether a key holds secrets (a throwing assembly, a resource without a stream, a spaced `configKey`, a plugin that loaded after the scan), the raw editor turns off rather than guessing.
- **ASF's IPC filters no `Host` header**, so a web page on the LAN can reach an IPC that only the LAN can reach (DNS rebinding). That is why raw reads need a real password even under the opt-in.
- **File mode.** The temp file starts as `File.Copy` of the original, which .NET creates with the original's mode before any content is copied. Owner, group and the folder's ACL are not carried over (relevant on Synology shares); the README says so.
- **The submodule and `.gitmodules` move together.** The bump workflow (`bump-asf-reference.yml`) verifies the new ASF release in a read-only job, then opens a pull request from a write job that runs no upstream code. Opening the PR needs either "Allow GitHub Actions to create and approve pull requests" (Settings > Actions > General) or an `ARCHIBOT_GITHUB_TOKEN` secret. **Its success path has not run live yet: check the first real bump run.**
- **A push or PR made with the default token starts no workflow**, hence the explicit `workflow_dispatch` of `ci.yml` in the bump job.
- **Worktrees.** Clone the submodule shallow (`git submodule update --init --depth 1`); a full clone took over 15 minutes. Remove a worktree with `git worktree remove --force` after checking it is clean.
- **Screenshots** live on the `pr-assets` branch under `<PR number>/` and `1.0.0.0/`, linked pinned to a commit. Never on `main`.

## Build and test

Requires the .NET 10 SDK and a recursive clone.

- `dotnet build -c Release` (warnings are errors) and `dotnet test ASFPluginConfig.Tests -c Release`. Two file-mode tests need Unix and are skipped on Windows; Linux CI runs them.
- Trimmed-ASF check, as in `CLAUDE.md`: unzip an official OS-specific ASF release, then `tools/TrimCheck` and `tools/smoke/smoke.sh` (34 checks, bash and `curl`; a win-x64 release works under Git Bash).

## Open issue

[#18](https://github.com/easly1989/ASF-PluginConfig/issues/18): a write by ASF in the instant between the last check of the file and the swap is lost. The save now compares the file once more after the flush, right before the swap, so only that instant is open. Closing it needs a lock across processes, and ASF takes none on its config files; the issue records why `File.Replace` with a backup is not worth it. Close it as a known issue unless ASF grows such a lock.
